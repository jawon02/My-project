# 수학 로그라이크 게임 - 현재 개발 목표 기획서
**대상:** Claude (수석 프로그래머)  
**프로젝트:** Unity / C# 기반 턴제 전략 로그라이크  
**개발 방향:** 1인 개발 / 초보 개발자 / MVP 우선

---

## 1. 프로젝트 개요

### 게임 컨셉
수학 공식과 기호를 공격 및 방어 수단으로 활용하는 턴제 전략 로그라이크 게임이다.

플레이어는 사칙연산부터 시작해 방정식, 함수, 그래프 등 다양한 수학 개념을 활용하는 카드와 스킬을 획득하고, 유물과 조합하여 자신만의 전투 빌드를 구성한다.

단순한 수학 교육용 게임이 아니라, 전략적인 카드 운용과 빌드 조합, 적의 행동 패턴 분석, 보스의 수학적 기믹 공략을 핵심 재미로 삼는다.

### 참고 게임의 방향성
- Slay the Spire: 카드 기반 턴제 전투와 분기형 로그라이크 진행.
- Into the Breach: 적의 행동 예고를 활용하는 전략적 대응.
- 수학적 공식과 기호를 활용한 독자적인 전투 및 보스 기믹.

위 게임들의 핵심적인 장점을 참고하되, 고유한 수학 전투 시스템을 구축한다.

## 2. 현재 개발의 최종 목표

우선 완성된 게임 전체를 만드는 것이 아니라, 핵심 전투 시스템이 실제로 작동하는 프로토타입을 만드는 것이 목표다.

### 1차 목표: 전투 프로토타입 완성

다음 기능이 정상적으로 작동해야 한다.

1. 플레이어와 적이 등장하는 전투 화면.
2. 플레이어 체력, 에너지, 방어도 표시.
3. 카드 손패 및 카드 사용 시스템.
4. 카드 사용 시 에너지 차감.
5. 공격 카드와 방어 카드 효과 적용.
6. 적의 행동 예고 표시.
7. 플레이어 턴 종료 및 적 턴 진행.
8. 적의 공격과 플레이어 방어도 계산.
9. 적 처치 및 전투 승리 판정.
10. 플레이어 체력 0 도달 시 게임 오버.

**1차 목표의 완료 기준:** 별도의 개발자 개입 없이 플레이어가 카드를 사용하고 적과 턴제 전투를 진행하여 승리하거나 패배할 수 있어야 한다.

## 3. 개발 단계별 목표

### Phase 1. 기본 전투 시스템

가장 먼저 구현할 단계다.

- 플레이어 기본 능력치 관리
- 적 기본 능력치 관리
- 플레이어 턴과 적 턴 구분
- 에너지 회복 및 소모
- 카드 사용
- 공격 및 방어 계산
- 적 행동 예고
- 적 행동 실행
- 승리 및 패배 판정

초기에는 적 1마리와 카드 몇 종류만 사용해도 된다.

### Phase 2. 카드 시스템 완성

- 시작 덱 10장 구성
- 공격 5장, 방어 4장, 특수 1장
- 카드 뽑기 더미
- 손패
- 버림 더미
- 카드 사용 및 이동
- 턴 시작 시 5장 드로우
- 손패 최대 10장
- 뽑기 더미 소진 시 버림 더미 셔플
- 카드 강화 기능

카드 데이터는 ScriptableObject 등 데이터 기반 구조로 설계하여 추후 새로운 카드를 쉽게 추가할 수 있도록 한다.

### Phase 3. 적과 전투 콘텐츠

- 일반 적 여러 종류
- 엘리트 적
- 보스
- 적별 고유 행동 패턴
- 행동 예고 시스템
- 적의 공격 및 지원 행동
- 다수 적 전투
- 보스별 특수 기믹

초기에는 일반 적을 먼저 완성하고 엘리트와 보스는 이후 추가한다.

### Phase 4. 성장 시스템

- 카드 보상
- 골드 보상
- 카드 선택 및 덱 추가
- 스킬 장착 및 사용
- 유물 획득 및 패시브 효과
- 버프와 디버프
- 유물 간 일부 시너지

### Phase 5. 로그라이크 진행 시스템

- 분기형 맵
- 일반 전투 노드
- 엘리트 노드
- 상점 노드
- 휴식 노드
- 이벤트 노드
- 보스 노드
- 구역 진행 및 런 종료
- 런 데이터 초기화

### Phase 6. 장기 콘텐츠

- 3개 구역 및 최종 보스
- 수학적 보스 기믹
- 영구 도감
- 콘텐츠 해금
- 추가 캐릭터
- 수학 공식 및 스킬 확장
- 추가 유물과 카드

## 4. 현재 개발에서 반드시 지켜야 할 원칙

### ① MVP 우선 개발
아직 구현하지 않은 기능을 한꺼번에 만들지 않는다.

작은 기능 하나를 구현하고 테스트한 후 다음 기능으로 넘어간다.

### ② 확장 가능한 구조
카드, 적, 스킬, 유물 등을 추가할 때 기존 시스템을 대규모로 수정하지 않도록 데이터 중심으로 설계한다.

### ③ 시스템 간 의존성 최소화
전투, 카드, 적, 유물, 맵, 영구 데이터 시스템을 적절히 분리한다.

### ④ 임의의 기획 변경 금지
기획서에 명시된 규칙을 임의로 변경하지 않는다.

구현 과정에서 충돌이나 문제가 발생하면 먼저 문제와 대안을 설명하고 사용자 확인을 받는다.

### ⑤ 초보 개발자도 유지보수할 수 있는 코드
- 클래스와 함수의 역할을 명확하게 구분.
- 복잡한 코드에는 주석 추가.
- 지나치게 추상화된 구조는 지양.
- 기존 프로젝트의 코드와 구조를 우선 확인.
- 불필요한 파일 및 시스템 생성 금지.

## 5. 초기 MVP에서 제외할 기능

다음 기능은 게임의 장기적인 방향에는 포함되지만 초기 전투 프로토타입에서는 구현하지 않는다.

- 복잡한 수학 공식 계산 시스템
- 수학 속성 상성 시스템
- 미적분 등 고급 수학 콘텐츠
- 다중 플레이어 캐릭터
- 복잡한 유물 시너지
- 방대한 이벤트 콘텐츠
- 영구 능력치 강화
- 복잡한 맵 자동 생성 알고리즘
- 온라인 기능 및 멀티플레이

초기에는 카드 효과를 데이터와 간단한 로직으로 구현하고, 수학적 개성은 카드와 스킬의 효과를 통해 표현한다.

## 6. Claude의 작업 방식

Claude는 수석 프로그래머 역할을 담당한다.

작업은 다음 순서로 진행한다.

1. 현재 Unity 프로젝트의 파일 및 폴더 구조 확인.
2. 기존 코드와 구현 상태 파악.
3. 현재 단계에서 구현할 기능 제시.
4. 필요한 클래스와 데이터 구조 설명.
5. 실제 코드 작성 및 수정.
6. Unity에서 테스트하는 방법 안내.
7. 예상되는 오류 및 주의사항 설명.
8. 현재 단계의 완료 여부 확인.
9. 완료 후 다음 개발 단계 제안.

한 번에 전체 게임 코드를 작성하지 않는다.

각 Phase를 독립적으로 테스트하고, 정상 작동을 확인한 다음 다음 Phase로 이동한다.

## 7. AI 협업 구조

- **ChatGPT:** 게임 기획 및 시스템 설계 담당.
- **Claude:** Unity/C# 구현 담당.
- **Gemini:** 코드 및 기능 QA, 테스트 결과 검토 담당.

기획 변경이 필요한 경우 ChatGPT와 협의하고, 구현 결과는 Gemini를 통해 검토한다.

## 8. Claude에게 전달하는 첫 번째 작업 지시

현재는 게임 전체를 구현하지 말고 다음 작업부터 시작한다.

**첫 번째 작업: Unity 프로젝트 구조 분석 및 기본 전투 프로토타입 설계**

1. 현재 Unity 프로젝트 구조를 먼저 확인한다.
2. 기존에 작성된 코드가 있다면 재사용 가능성을 검토한다.
3. 기본 전투 프로토타입에 필요한 클래스와 파일 목록을 제안한다.
4. 플레이어와 적의 기본 능력치 관리 구조를 설계한다.
5. 카드 사용과 턴 진행 구조를 설계한다.
6. 구현 순서와 테스트 방법을 설명한다.
7. 사용자 확인을 받은 뒤 실제 코드 작성을 시작한다.

최우선 목표는 화려한 UI나 방대한 콘텐츠가 아니라, **플레이어가 카드를 사용하고 적의 행동에 대응하며 전투에서 승리하거나 패배하는 핵심 게임 루프를 완성하는 것**이다.

이 목표를 달성한 뒤 다음 개발 단계로 넘어간다.
