## 3. 클래스 연결 관계

```
CombatManager ─ 연결 ─> PlayerController ─ 연결 ─> CardManager
      │                        │                       │
      │                        └ combatant(Combatant)   └ startingDeck(CardData 목록)
      │                                                   runDeck/drawPile/hand/discardPile (CardInstance 목록)
      └ enemies / livingEnemies ─> EnemyController ─ data ─> EnemyData
                                         └ combatant(Combatant)
```

- `CombatManager`가 전체를 조율하고, 나머지는 서로의 세부 구현을 모른다.
- 카드 사용 흐름: `CombatManager.PlayCard(i)` → 카드의 `TargetType`으로 대상 결정(공격·Buff 카드만. 단일 = 선택된 적 / 전체 = 살아 있는 적 전부 왼쪽부터 / 무작위 = 1명 / Self = 빈 목록) → `PlayerController.TryPlayCardOnTargets(i, 대상 목록)` → (에너지 지불 → 효과(공격·방어는 플레이어 보정 적용, Buff는 효과 걸기, 재정렬은 드로우) → `CardManager.DiscardFromHand`) → 살아 있는 적 예고 재계산 → 사망한 적 제거 → 대상 자동 변경 → 전부 처치 시 승리(한 번 판정)
- 적 턴 흐름: `CombatManager.RunEnemyTurn()` → 살아 있는 적을 리스트 순서대로 `EnemyController.ExecuteAction(player.combatant)`(방어도 초기화 → 보정된 행동 → 효과 지속시간 감소 → 다음 예고) → 플레이어 사망 시 즉시 패배
- 상태 효과: `Combatant.statusEffects`에 저장 (플레이어·적 공통). 플레이어는 `PlayerController.EndTurn()`, 적은 `ExecuteAction` 끝에서 지속시간 감소. `CombatManager.EndBattle()`(승리·패배)에서 전부 제거, `StartBattle()`에서도 비움
- 런 시작: `CombatManager.StartRun()` = `PlayerController.InitRun()` + `CardManager.StartRun()` (전투는 시작하지 않음)

### 나중에 UI가 사용할 부분 (UI 프로토타입 단계)
- **호출**: `CombatManager.PlayCard(handIndex)`, `EndPlayerTurn()`, `StartRun()`, `StartBattle()`, `SelectEnemy(칸)` (적 클릭)
- **읽기 전용 상태**: `player.combatant.currentHp/maxHp/block/statusEffects`, `player.energy/maxEnergy`, `cardManager.hand`(각 `CardInstance`의 `Name/Cost/Value/Type`), `drawPile.Count`, `discardPile.Count`, `livingEnemies`(각 적의 `combatant`, `nextActionPreview`), `enemies`(고정 칸 번호), `selectedEnemyIndex`, `combat.state`
- 로직 스크립트는 UI를 참조하지 않는다. UI → 로직 방향의 호출만 있다.

## 5. 조작법 (Play 모드)

- `CombatManager`의 `Start On Play`가 켜져 있으면 Play 시 자동으로 런 + 전투 시작
- **Game 창을 한 번 클릭**해서 포커스를 준 뒤: 숫자 `1~9`, `0` = 손패 1~10번째 카드 사용, `Space` = 플레이어 턴 종료, `←`/`→` = 대상 변경(끝에서 멈춤), `Tab` = 다음 살아 있는 적(순환)
- Unity의 새 Input System과 예전 Input Manager를 모두 지원하는 `#if` 구문을 사용

## 6. 주의사항

1. **파일 이름 = 클래스 이름**이어야 한다. (Unity 규칙)
2. 파일을 교체할 때는 같은 이름 파일을 덮어쓴다.
3. `CardData.upgradedValue` 기본값은 **0**이다. 강화가 필요한 카드는 인스펙터에서 직접 채워야 한다.
4. `CardManager`의 필드 `deck`은 `startingDeck`으로 이름이 바뀌었다(`FormerlySerializedAs`로 기존 값 유지).
5. 인스펙터의 `Run Deck`, `Draw Pile` 등은 **확인용**이다. 직접 수정하지 말 것.
6. 적이 죽으면 `SetActive(false)`로 숨겨진다. 다음 `StartBattle()`에서 다시 켜진다. 테스트 후 적 오브젝트가 회색으로 보일 수 있다.
7. 자동 테스트는 **적 2마리(슬라임 40 / 7→5→10)** 와 위 카드 수치를 전제로 한다.
8. Claude는 Unity에서 직접 컴파일할 수 없다. 컴파일 에러가 나면 메시지를 그대로 전달한다.
9. `Debug.LogWarning`이 일부 테스트 중 나오는 것은 정상이다. (일부러 실패 상황을 만드는 테스트)
10. 카드 사용 함수는 두 개다: `TryPlayCard(i, 대상 1명)`과 `TryPlayCardOnTargets(i, 대상 목록)`. 이름이 다른 이유는 `TryPlayCard(0, null)` 호출이 모호해져 컴파일 에러가 나는 것을 막기 위해서다.
11. 새 카드를 만들면 Target Type을 꼭 확인한다. 기본값은 SingleEnemy라서 방어·자기 강화 카드는 Self로 바꿔야 한다.
12. Buff 카드는 `Status Effect`를 꼭 지정한다. None이면 사용 실패(경고 로그)이고, Duration이나 value가 0이면 카드는 사용되지만 효과는 걸리지 않는다.
13. 에디터 로그는 프로젝트 폴더의 `Logs/Editor.log`에 쌓인다. (`%LOCALAPPDATA%\Unity\Editor\Editor.log`에는 Unity 시작 부분만 있다)
14. 적 행동 예고는 상태 효과를 반영한다. 효과가 없으면 `공격 7`, 있으면 `공격 5 (기본 7, 공격력 감소 -2)`.
