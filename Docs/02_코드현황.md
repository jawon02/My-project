# 코드 현황 문서

> 코드의 실제 기준은 **업로드된 최신 스크립트 파일**이다. 이 문서는 구조를 빠르게 파악하기 위한 요약이다. 둘이 충돌하면 임의로 판단하지 말고 사용자에게 알린다.
> 최종 갱신: 2026-11-23 / Unity 6.2 / 스크립트 위치: `Assets/_Project/Scripts/Battle`

## 3. 클래스 연결 관계

```
CombatManager ─ 연결 ─> PlayerController ─ 연결 ─> CardManager
      │                        │                       │
      │                        └ combatant(Combatant)   └ startingDeck(CardData 목록)
      │                                                   runDeck/drawPile/hand/discardPile (CardInstance 목록)
      └ enemies / livingEnemies ─> EnemyController ─ data ─> EnemyData
                                         └ combatant(Combatant)
```

- `CombatManager`가 전체를 조율하고, 나머지는 서로의 세부 구현을 모른다.
- 카드 사용 흐름: `CombatManager.PlayCard(i)` → `PlayerController.TryPlayCard(i, 대상 Combatant)` → (에너지 지불 → 효과 → `CardManager.DiscardFromHand`) → 사망한 적 제거 → 전부 처치 시 승리
- 적 턴 흐름: `CombatManager.RunEnemyTurn()` → 살아 있는 적을 리스트 순서대로 `EnemyController.ExecuteAction(player.combatant)` → 플레이어 사망 시 즉시 패배
- 런 시작: `CombatManager.StartRun()` = `PlayerController.InitRun()` + `CardManager.StartRun()` (전투는 시작하지 않음)

### 나중에 UI가 사용할 부분 (UI 프로토타입 단계)
- **호출**: `CombatManager.PlayCard(handIndex)`, `EndPlayerTurn()`, `StartRun()`, `StartBattle()`
- **읽기 전용 상태**: `player.combatant.currentHp/maxHp/block`, `player.energy/maxEnergy`, `cardManager.hand`(각 `CardInstance`의 `Name/Cost/Value/Type`), `drawPile.Count`, `discardPile.Count`, `livingEnemies`(각 적의 `combatant`, `nextActionPreview`), `combat.state`
- 로직 스크립트는 UI를 참조하지 않는다. UI → 로직 방향의 호출만 있다.

## 5. 조작법 (Play 모드)

- `CombatManager`의 `Start On Play`가 켜져 있으면 Play 시 자동으로 런 + 전투 시작
- **Game 창을 한 번 클릭**해서 포커스를 준 뒤: 숫자 `1~9`, `0` = 손패 1~10번째 카드 사용, `Space` = 플레이어 턴 종료
- Unity의 새 Input System과 예전 Input Manager를 모두 지원하는 `#if` 구문을 사용

## 6. 주의사항

1. **파일 이름 = 클래스 이름**이어야 한다. (Unity 규칙)
2. 파일을 교체할 때는 같은 이름 파일을 덮어쓴다.
3. `CardData.upgradedValue` 기본값은 **0**이다. 강화가 필요한 카드는 인스펙터에서 직접 채워야 한다.
4. `CardManager`의 필드 `deck`은 `startingDeck`으로 이름이 바뀌었다(`FormerlySerializedAs`로 기존 값 유지).
5. 인스펙터의 `Run Deck`, `Draw Pile` 등은 **확인용**이다. 직접 수정하지 말 것.
6. 적이 죽으면 `SetActive(false)`로 숨겨진다. 다음 `StartBattle()`에서 다시 켜진다. 테스트 후 적 오브젝트가 회색으로 보일 수 있다.
7. 자동 테스트는 **적 2마리(슬라임 40 / 7→5→10)** 와 위 카드 수치를 전제로 한다.
8. Claude는 Unity에서 직접 컴파일할 수 없다. 컴파일 에러가 나면 메시지를 그대로 전달한다.
9. `Debug.LogWarning`이 일부 테스트 중 나오는 것은 정상이다. (일부러 실패 상황을 만드는 테스트)
