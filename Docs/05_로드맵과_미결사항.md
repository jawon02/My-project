# 로드맵과 미결사항

> 최종 갱신: 2026-11-23. 순서는 **제안안**이며 ChatGPT와 협의해 확정한다. 확정된 규칙은 01_결정로그.md 참고.

## 1. 로드맵

| 단계 | 내용 | 상태 |
|---|---|---|
| Phase 1 | 기본 전투 (Combatant, 카드·적 데이터, CardManager, PlayerController, EnemyController, CombatManager) | **완료** (키보드 실플레이 통과) |
| Phase 2 | CardInstance, startingDeck/runDeck 분리, 카드 개별 강화 | 구현 완료, **테스트 결과 대기** |
| Phase 3 | 다수 적 공격 대상 선택 (단일 / 전체 / 무작위). UI 전에는 키보드로 임시 선택 | 다음 단계 (영향 분석 먼저) |
| Phase 4 | 버프·디버프(4종), 적 행동 5종, 재정렬 카드 효과 | 규칙 확정, 세부 수치 미결 |
| UI 프로토타입 (제안) | 체력·에너지, 손패 클릭, 적 클릭 대상 선택, 턴 종료 버튼, 승패 화면 | Phase 4 직후 제안 |
| Phase 5 | 카드 보상, 골드 | 진입 전 재결정 필요 |
| 수학 공식 시스템 1차 (제안) | 수학 분류, 공식 표현, 연산 기반 효과(예: 곱셈 증폭), 카드 설명, 도감 연동 | 게임 정체성 핵심. Phase 5와 순서 조정 가능 |
| 이후 | 스킬·유물, 분기형 맵, 상점, 휴식(카드 강화 연결), 이벤트, 보스 기믹, 도감 UI, 영구 저장 | |

## 2. 미결사항 (ChatGPT 결정 필요)

### Phase 3 전
1. 카드 데이터에 공격 방식을 표시하는 방법 (제안: `CardData`에 `targetType` 필드 추가)
2. 단일 공격 대상 선택을 UI 전에 키보드로 임시 처리해도 되는지 (카드 번호 → 적 번호)

### Phase 4 전
3. `SelfBuff` / `AllyBuff` / `AllyHeal`의 구체 효과와 수치
4. 아군 대상을 "하나" 고르는 기준 (무작위 / 리스트 순서)
5. 플레이어용 `Buff` 카드가 주는 효과와 수치
6. 버프 최종 계산에서 공격력 보정이 카드 `value`에 적용되는 방식 확인 (확정식: Max(0, 기본 + 보정))

### Phase 5 전
7. 카드 풀 구성과 카드별 등급 지정
8. 골드 획득량, 상점 가격
9. 보상 건너뛰기 여부

### 밸런스
10. 카드 강화 수치의 최종값 (현재 타격 9 등은 검증용 임시값)
11. 임시 카드(Strike, Guard 등)를 대체할 실제 수학 카드 설계

### 수학 시스템 (해당 단계 진입 전)
12. 수학 분류 체계, 공식 표현 방식, 카드의 수학적 효과와 강화의 관계
13. 도감 데이터 구조와 해금 조건
