# 수학 로그라이크 게임 - 1차 구현 명세서

## 1. 구현 목적

수학 공식과 기호를 활용하는 턴제 전략 로그라이크 게임의 핵심 시스템을 Unity C#으로 구현한다.

초기 목표는 콘텐츠 전체를 한 번에 구현하는 것이 아니라, 플레이어와 적이 정상적으로 전투를 진행하고 카드·스킬·유물 시스템이 작동하는 MVP 프로토타입을 만드는 것이다.

## 2. 핵심 게임 규칙

### 플레이어
- 기본 최대 체력: 70 (초기 밸런스 제안값)
- 시작 체력: 최대 체력과 동일
- 기본 최대 에너지: 3
- 전투 시작 방어도: 0
- 턴 시작 카드 드로우: 5장
- 손패 최대: 10장

### 카드
- 시작 덱: 공격 5장, 방어 4장, 특수 1장
- 모든 시작 카드는 미강화 상태
- 카드 등급: 일반, 희귀, 전설
- 등급 생성 확률: 70%, 25%, 5%
- 카드 비용: 0~5 에너지
- 카드 사용 순서: 에너지 확인 및 지불 → 효과 적용 → 버림 더미 이동
- 사용 카드와 턴 종료 시 남은 카드는 버림 더미로 이동
- 뽑기 더미가 비면 버림 더미를 섞어 새 뽑기 더미 생성
- 손패가 10장을 초과하면 초과 카드는 버림 더미로 이동
- 카드 강화는 기본 수치만 증가

### 에너지
- 플레이어 턴 시작 시 최대치까지 회복
- 카드와 스킬이 동일한 에너지 사용
- 에너지가 부족하면 사용 불가
- 턴 종료 시 남은 에너지 소멸
- 최대 에너지는 카드와 유물 효과로 증가 가능

### 턴 진행
1. 플레이어 턴 시작
2. 에너지 회복
3. 카드 5장 드로우
4. 플레이어 카드 및 스킬 사용
5. 플레이어 턴 종료
6. 남은 손패 버림
7. 방어도 초기화
8. 적 행동 실행
9. 다음 플레이어 턴

에너지가 0이 되면 자동 종료하되, 사용 가능한 0코스트 카드가 손에 남아 있다면 해당 카드를 사용할 기회를 유지한다.

### 방어도와 체력
- 적 공격은 플레이어 방어도를 먼저 감소시킨다.
- 방어도로 막지 못한 피해만 체력에 적용한다.
- 플레이어 턴 종료 시 방어도 초기화
- 전투 시작 시 방어도 0
- 체력이 0 이하가 되면 즉시 게임 오버
- 전투 승리 후 자동 체력 회복 없음

### 적
- 적마다 고유 행동 패턴 보유
- 일반 적: 다음 행동 1개 예고
- 엘리트: 다음 행동 및 특수 조건 예고
- 보스: 여러 턴 행동 패턴 예고
- 적 행동 순서: 화면 왼쪽부터 오른쪽
- 적 체력 0 이하 시 즉시 제거
- 제거된 적은 행동하지 않음
- 모든 적 처치 시 전투 종료
- 적 회복은 최대 체력을 초과할 수 없음
- 적은 공격, 방어, 자기 강화, 아군 강화, 아군 회복 등의 행동을 가질 수 있음

### 버프와 디버프
- 지속시간은 턴 단위
- 플레이어 효과: 플레이어 턴 종료 시 지속시간 감소
- 적 효과: 해당 적의 턴 종료 시 지속시간 감소
- 같은 효과 재적용 시 수치는 중첩하지 않고 지속시간 갱신
- 반대 효과는 독립적으로 적용
- 최종 능력치는 모든 효과를 합산
- 공격력 및 방어력 등 최종 능력치는 최소 0
- 전투 종료 시 임시 효과 제거

## 3. 로그라이크 진행

- 총 3개 구역 + 최종 보스
- 각 구역은 분기형 맵
- 노드 종류: 일반 전투, 엘리트, 상점, 휴식, 이벤트, 보스
- 구역 마지막에 구역 보스 배치
- 3구역 이후 최종 보스 배치
- 런 종료 시 체력, 골드, 카드, 유물, 임시 강화 초기화
- 도감 및 영구 콘텐츠 해금 기록은 유지
- 영구 능력치 강화 시스템은 없음

## 4. 카드 보상 및 상점

- 전투 승리 후 카드 보상 또는 골드 보상 선택
- 카드 보상: 무작위 3장 중 1장 선택
- 상점 기능: 카드 구매, 유물 구매, 카드 제거
- 카드 제거는 현재 런에서 복구 불가
- 구매한 상품은 상점에서 제거
- 상점 퇴장 후 재방문 불가
- 골드 부족 시 구매 불가

초기 가격 및 보상 수치는 별도 데이터로 관리한다.

## 5. 스킬 시스템

- 스킬은 별도 슬롯에 장착
- 초기 스킬 슬롯 2개
- 카드와 동일한 에너지 사용
- 에너지가 충분하면 반복 사용 가능
- 전투 중 교체 불가
- 전투 승리 후 장착 및 교체 가능
- 스킬은 보스, 이벤트, 특수 조건으로 획득
- 영구 해금 스킬은 이후 런에서 획득 후보가 될 수 있음

## 6. 유물 시스템

- 초기 MVP 유물은 패시브 효과 중심
- 유물 보유 개수 제한 없음
- 기본적으로 각 유물은 독립적으로 작동
- 일부 핵심 유물 조합에만 시너지 효과 부여
- 보스 처치 시 보스 전용 유물 1개 확정 획득
- 유물은 런 종료 시 초기화
- 도감 발견 기록은 영구 유지

## 7. 추천 클래스 구조

- GameManager: 게임 전체 상태 및 진행 관리
- CombatManager: 전투 시작, 종료, 턴 진행 관리
- PlayerController: 플레이어 체력, 에너지, 방어도 관리
- EnemyController: 적의 체력 및 행동 관리
- EnemyAction: 적의 행동 데이터와 실행 로직
- CardData: 카드 이름, 비용, 등급, 효과 데이터
- CardManager: 덱, 손패, 뽑기 더미, 버림 더미 관리
- SkillData: 스킬 데이터
- SkillManager: 스킬 장착 및 사용 관리
- RelicData: 유물 데이터
- RelicManager: 유물 획득 및 패시브 효과 관리
- StatusEffect: 버프 및 디버프 데이터와 지속시간 관리
- MapManager: 분기형 맵 및 노드 관리
- RewardManager: 전투 보상 처리
- ShopManager: 상점 구매 및 카드 제거
- RunManager: 런 시작, 진행, 종료 및 초기화
- CodexManager: 영구 도감 및 해금 데이터 관리

클래스 이름과 파일 분리는 기존 Unity 프로젝트 구조에 맞춰 조정 가능하다.

## 8. 구현 시 주의사항

1. 카드, 적, 스킬, 유물은 가능한 한 ScriptableObject 또는 데이터 기반으로 관리한다.
2. 밸런스 수치를 코드에 직접 하드코딩하지 않는다.
3. 런 단위 데이터와 영구 데이터를 반드시 분리한다.
4. 카드 사용 중 전투가 종료되면 후속 효과가 실행되지 않도록 처리한다.
5. 사망한 적은 행동 순서에서 즉시 제외한다.
6. 버프와 디버프의 지속시간 감소 시점을 명확하게 관리한다.
7. 적 행동 예고와 실제 실행 행동이 반드시 일치해야 한다.
8. 초기 구현은 일반 전투 1개를 완성한 뒤 콘텐츠를 확장한다.
9. 초기 MVP에서는 복잡한 수학 공식 계산 시스템과 속성 상성을 구현하지 않는다.
10. 이후 카드와 보스 콘텐츠를 추가하기 쉽도록 확장 가능한 구조를 유지한다.

## 9. 구현 우선순위

1단계: 플레이어와 적의 기본 전투
2단계: 에너지, 카드 드로우, 손패 및 버림 더미
3단계: 적 행동 패턴 및 행동 예고
4단계: 버프, 디버프, 방어도
5단계: 카드 보상과 덱 관리
6단계: 스킬 및 유물
7단계: 분기형 맵과 노드
8단계: 상점, 휴식, 이벤트
9단계: 보스 기믹 및 도감

각 단계는 개별 테스트를 통과한 후 다음 단계로 진행한다.
